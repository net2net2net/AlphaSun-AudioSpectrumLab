## 二、关键算法与它们的设计理由

### 2.0 跨模块麦克风协调（v2.20.0，最易踩的坑）
- **问题**：全项目有 **5 路独立 `getUserMedia`**（主采集 `start` / 环境 `envStartCapture` / 值守 `alBegin` / 转写 `asrCapStart` / 二级台 `l2LiveOwnMic`），彼此互不知情。任一路异常残留就占住设备，其余全部撞上 `NotReadableError`（用户看到「麦克风被其他程序占用」）→ **一个模块失败、锁死全部采集**。
- **对策 `releaseGhostMic(keep)`**：任一采集启动前，释放「其它模块处于非活跃态却仍残留」的流 + 二级台自开流。`keep`（`'main'`/`'env'`/`'guard'`/`'asr'`）标记发起者，**不夺正在使用的设备**。接入全部四个采集入口。
- **`*CapStart` 异常路径必须兜底**：`getUserMedia` 成功后再做 `addModule`/`new AudioWorkletNode` 等可能抛错的初始化，抛错时流已开 → 用 `try/catch` 失败即释放并 `throw`；上层 catch 还要**释放 + 复位按钮**（只 `toast` = 永久占用 + UI 卡死）。
- **防重复开流标志**必须在 `getUserMedia` **之前**同步置位、`finally` 复位，不能放 `.then` 链末（慢设备下并发开多路流）。

### 2.1 频率计权声级 dB(A)/dB(C)（v2.13.0）
- 公式：IEC 61672-1 的 A / C 计权网络解析式，逐 bin 预计算为**能量域增益**（`l2WeightTab`，按 `bin 数 + 频率分辨率` 缓存，采样率不变只算一次）。
- 合成必须在**能量域**：`Lw = 10·lg Σ 10^((Li+Wi)/10)`。直接对 dB 相加是错的。
- 边界：这是**相对满量程的数字电平**，未经麦克风灵敏度校准，不能当合规声压级。
- 用途：`dB(C) − dB(A)` 差值大 ⇒ 能量集中在低频（空调/引擎/风机嗡鸣）。
- **自检**：`tools/algo-selftest.js` 用 IEC 61672-1 标称值（31.5Hz–16kHz 共 10 点）比对，误差 <0.8dB。
  - 历史缺陷：分子曾写成 `f³`（应为 `f⁴`），导致 1kHz 处整体偏低约 60dB —— 自检抓到。

### 2.2 统计声级 Leq / L10 / L50 / L90（v2.13.0）
- 基于 120s 滚动窗口的 dB(A) 序列（`SL_CAP=600`），至少 12 个有效帧（`SL_MIN`）才出数。
- Leq 是**能量平均**（`10lg(mean(10^(L/10)))`），不是算术平均——对突发声更敏感。
- 百分位定义别搞反：**Ln = 有 n% 的时间超过该声级** → L10 是第 90 百分位（峰值背景），L90 是第 10 百分位（本底）。
- 只统计「算得出计权值的帧」：信号弱到全频段 `-Infinity` 时该帧不计入，否则会污染统计。
- 不足阈值时显示「累计中 n/12 帧」，避免用户对着「—」以为坏了。

### 2.3 节拍 BPM（v2.13.0 重写）
- **原实现是确定性缺陷**：用 `runAnalysis` 的 200ms 包络，却在 `lag=8..59` 搜索 → 换算后 BPM 仅 5.08–37.5，**恒不满足 `50<bpm<200` 的返回门限 ⇒ 永远返回 0**（BPM 事实上从未工作过）。
- 现实现：
  1. 包络改为 rAF 帧级（`envFast`，≈16ms/帧，容量 320）；
  2. 去均值 + **归一化**互相关（裸自相关随 lag 增大天然衰减，会系统偏向最短 lag）；
  3. lag 范围由真实 BPM 上下限反推，dt 取实测平均帧间隔（不写死，兼容 60/90/120Hz 屏）；
  4. **倍频歧义消解**：脉冲串自相关在 2/3 倍周期处同样很高（实测 150BPM 会判成 50BPM），在 ≥0.85×峰值的候选中优先取落在 [70,180] 的较快者；
  5. **稀疏性门** `hotRatio > 0.15` 则拒绝：节拍是稀疏瞬态，语音音节率（4–6Hz）会被误判成节拍。门限由实测标定（理想节拍 0.02–0.04；平稳噪声 0.23、语音式起伏 0.20、缓慢正弦 0.27）。
- **自检**：60/75/90/100/120/140/150/180 BPM 全部命中（误差 ≤6）；平稳噪声、语音式起伏、缓慢正弦、白噪抖动全部拒绝为 0。

### 2.4 基频 F0
- 自相关 + 峰值突出度门（`mv/c[0] ≥ 0.30` 且 `mv ≥ 1.6×全体滞后均值`）+ 抛物线亚样本插值。
- 单看 `mv/c[0]` 不够：粉噪/棕噪的自相关在所有滞后上都偏高（缓慢衰减），会误判出周期。

### 2.5 分类（classify）
- 四类（人声/音乐/其他声音/噪音）透明加权 + softmax。权重经多轮实测调平衡，**不要凭直觉改**。
- 音乐判据三支柱：谐波 + 持续 + 节拍。BPM 修复后会更易触发——已用稀疏性门控制假阳性。
- 「其他声音」细化是模板匹配启发式，非训练模型；同类声源重叠必然混淆。

### 2.6 声源定位
- GCC-PHAT 广义互相关 + 双曲线交汇。
- 单声道设备（绝大多数手机/笔记本内置麦）自动启用虚拟 3 麦三角阵仿真；v2.12.0 起随「开始采集」自动开启。真实多声道接入时 `setupArray` 自动接管并退出仿真。

### 2.7 语音转写架构（v2.15.0 起，v2.19.0 升级为自动升降级）
- **云端通道放主进程**：浏览器直连 DashScope 会被 CORS 拦、且 Key 会暴露在前端。
  `main.js` 内做「上传凭证 → OSS 上传 → 提交异步任务 → 轮询 → 取逐句」，`preload.js` 用 contextBridge
  暴露 `window.asrCloud`，渲染层**只传 WAV base64**。
- **云端是非实时文件转写**（做不到流式）→ 前端用「分段录制 + 分段提交」准实时（段长 20/30/60s，停止时补交尾段）。
  这点在 UI 与文档里必须说清，不能让用户期待逐字实时。
- **引擎优先级与自动升降级（v2.19.0）**：`asrBestEngine()` 依次探测
  **云端 DashScope（`keyStatus().hasKey`）→ 本地 Vosk（离线模型 HEAD 探测）→ 浏览器 Web Speech → 不支持**。
  `auto`（默认）模式下 `asrAutoTick()` 每 12s 比对，转写进行中平滑切换（云端恢复自动升级回云端）。
  徽标前缀「自动 · 」如实标注当前链路。
- **Vosk 无官方粤语模型**：`vosk-model-small-yue` 系列 404 → **粤语只能走云端**，本地必须明确拒绝，不可谎报。
- **Electron 不支持 `window.prompt`**：云端 Key 配置必须是**面板内联输入框**（v2.18.0 修复的崩溃点）。
- 采集器 `ASR_CAP` 统一供波形/WAV/Vosk 共用；`capSlice` 在提交后重建 chunks 丢弃已提交部分，防长时录制内存无界增长。
- **Web Speech 会话（`recog`）管理（v2.23.0，关键）**：`SpeechRecognition` 是**独立于 MediaStream 的
  麦克风占用源** —— 主采集 `start()` 内的 `setupASR()` 会新建它并 `.start()`，**隐式独占麦克风**。
  - 统一用 `recogStopSession()` 释放：`abort()`（比 `stop()` 更硬、立即释放）+ `stop()` + 摘除全部回调 + **置 `recog=null`**。
  - `setupASR()` 先终止旧会话再新建；`stop()` / `asrStop()` / `asrAutoTick()` 引擎切换全部走它。
  - `recog` 被主采集与转写**共用**，两者都会覆写它的 `onend`（主采集按 `running`、转写按 `asrOn` 重启）——
    这是共享句柄的固有设计，释放时务必摘除回调避免互相触发。
  - ⚠ 若新增任何会隐式占麦的 API（如 Web Speech、MediaRecorder），**必须接入 `releaseGhostMic` / `recogStopSession` 体系**，否则会重演「一个模块残留锁死全部采集」。

### 2.8 值守台判定模型（v2.17.0 起）
- 开局先做**本底评估**（取 L90 避开偶发峰）→ 预警 = 本底 + 预警余量、告警 = 本底 + 告警余量。
  v2.17.0 起改为「本底 + 余量」判定，**移除了旧的方向选择器**（`alertDir` 已删除）。
- 状态机 `idle → eval（评估）→ normal(蓝) / warn(黄) / alarm(红)`；回落持续 N 秒结束事件，单事件有最长时长保护。
- 环谱着色：`alDrawRing()` 按 `GUARD.state` 整环 + `boxShadow`（正常蓝 / 预警黄 / 告警红），v2.19.0 缩小为顶部中央 150×150 不遮挡主波形。

## 三、崩溃防线（**不要回退**）

1. **Electron 的 `decodeAudioData` 会 native crash 渲染进程**（对任何音频，含最简 48k 单声道 WAV；与 `--no-sandbox`/`--disable-gpu` 无关，try/catch 拦不住）。
   → 全项目改用 **`l2ParseWav`（纯 JS 解析 WAV）+ `l2BufLike`（AudioBuffer 兼容壳）+ 统一入口 `l2DecodePCM`**。
   → 录制走 **AudioWorklet 直采 PCM → WAV**（`ASREC_SRC`），产物与导入 WAV 同构，不再是 webm。
   → `l2IsWebm` 在载入/处理/声谱图/转码前拦截 webm（MediaRecorder 产物 `duration=Infinity`）。
2. **OOM 防线**：解码前 `l2PeekDur` 时长预检；≤40MB / ≤600s（处理）/ ≤900s（波形）；`ab=null`、`buf=null`、`chs.length=0` 尽早释放。
3. **异常不能静默**：`analyzeLoop` 的 try/catch 会吞掉帧内异常。新增指标若依赖未声明变量，会表现为「功能不生效但不报错」——**新增代码必须跑 `tools/pw-metrics-check.js` 确认真的出数**。
4. **FLAC 编码**：WebCodecs 在 Electron/Edge 均不支持 flac/mp3 → 自研 `l2EncFlacJS`（FIXED(order2) + Rice，无收益时降级 VERBATIM，CRC-8/CRC-16）。全平台可用。
5. **`ScriptProcessorNode` 在本机 Electron 28 下必崩**（v2.17.0/v2.17.1 两次实测：点开始即 `[CRASH] renderer crashed`）。
   全项目录音支路统一改用 **AudioWorklet `as-rec` 直采 PCM**，并经零增益节点汇入 destination（只为让节点被拉取、不回放）。
   `index.html` 内 `ScriptProcessorNode` 计数应恒为 **0**。
6. **AudioWorklet 回调拿的是 `Float32Array` 而非 `AudioBuffer`**：Vosk 的 `acceptWaveform` 需要 AudioBuffer，
   故**仅在 Vosk 实际启用时**现场 `createBuffer + copyToChannel` 还原（常态零开销）。

## 五、UI 面板收尾约定（v2.23.1 新增，**不要回退**）

> 背景：v2.23.1 定位到麦克风占用的**真凶** —— 三个工具面板的关闭路径（✕ 按钮 / 点遮罩空白 / Esc 键）
> 自 v2.13.x 起**全部只移除 CSS 类、不停止任何采集**。用户「开始转写」后点 ✕ 关面板，
> 采集仍在后台占着麦克风 → 之后所有采集 `NotReadableError`，而外部查不到占用。

**约定：凡打开采集/播放/监听的 UI，其所有关闭入口必须调同一个幂等收尾函数。**

当前实现：`closeToolPanel(maskId)`（index.html）—— 先停采集再隐藏，三条关闭路径统一走它：

| 面板 | 关闭时执行 |
|---|---|
| `asrMask` | `asrStop()`（含 `recogStopSession()` 终止识别会话） |
| `envMask` | `envStopAll('关闭面板')` |
| `alertMask` | `alStopAll('关闭面板')` |

**新增面板/模块时必须遵守**：
1. 绝不能出现「多处各写一遍 `classList.remove('on')`」—— 必然漏掉停止逻辑；
2. 关闭函数必须**幂等**（未启动时调用无副作用）；
3. 关闭后**麦克风/摄像头必须已释放**，用 `window.__micDiag()` 可验证所有句柄 `active=false`。

配套的诊断与自愈：
- `window.__micDiag()` —— 在闭包内定义、显式挂 window（因自动化读不到闭包符号），
  返回每个句柄 `{name, tracks, ctxState, active}`；真机诊断脚本 `tools/mic-diag.js`（不加假设备参数）。
- `start()` 的 `openMic()` 外包一层自愈重试：遇「被占用」类失败 → 全量清理 → 等 220ms → 重试一次。

## 六、新增一个分析指标的标准动作

1. HTML 加 `<div class="row clk" data-p="key">…<span class="v" id="xxxV">—</span>…`
2. `E{}` 登记 `xxxV:$('xxxV')`
3. `PARAM_INFO` 登记（决定弹层说明与曲线色）
4. `pFmt` 视需要加格式分支
5. `runAnalysis` 计算并写入 `E.xxxV`
6. `phPush({...})` 加入（否则没有历史曲线）
7. `node tools/check.js` 全绿 + `tools/pw-metrics-check.js` 确认出数
8. `CHANGELOG.md` 追加一条

## 七、多平台差异

- Electron（Win/Linux/mac）：`main.js` 自动授权麦克风；`desktop/boot.js` 平台层。
- Android：Capacitor + WebView；v2.11.2 起录制走 AudioWorklet，产物为 WAV。麦克风需 `RECORD_AUDIO` **和** `MODIFY_AUDIO_SETTINGS` 两个权限（缺后者 `getUserMedia` 永远失败），且**不要覆写 `WebChromeClient`**（会丢掉 Capacitor 原生的权限检查链）。
- iOS：必须经 Capacitor 原生壳（`file://` 下 WebView 不允许音频采集）。
- PWA：`sw.js` 缓存清单需包含 `assets/lame.min.js`，否则离线下 MP3 导出失效（`tools/check.js` 第 5 步会校验）。
